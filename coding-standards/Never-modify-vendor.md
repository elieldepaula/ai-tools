# Never modify vendor

This is a HARD RULE in this project. The `vendor/` directory is read-only. NEVER edit files under `vendor/`, including Magento core, third-party modules and Composer packages.

## Why

- `vendor/` is generated by Composer; `composer install/update` wipes and recreates it. Any edit is lost on the next install.
- Changes to vendor code are not tracked in the repository, so they are invisible to review and break reproducibility.
- Forking/editing vendor code prevents upgrades and creates a maintenance debt for the whole team.

## Forbidden

- Editing any file under `vendor/`.
- Copying vendor code into the project and modifying it (duplicate/fork) to work around a bug.
- Adding code to core classes through preferences that simply re-implement core logic (see `Plugins-over-Preferences.md`).

## Correct patterns

### 1. Plugins (interceptors)

Extend or modify behavior without touching the original class. Works when the target is a class instance.

```xml
<type name="Magento\Catalog\Model\Product">
    <plugin name="acme_product_after_save" type="Acme\Catalog\Plugin\ProductPlugin" sortOrder="10"/>
</type>
```

### 2. Events and observers

Hook into core flows using events (`events.xml`). Use `sales_model_service_quote_submit_success`, `catalog_product_save_after`, etc.

### 3. Virtual types

Reconfigure classes without editing them (`di.xml` `virtualType`), e.g. to change arguments or swap factory behavior.

### 4. Composer patches

For genuine core/third-party bugs that cannot be solved with plugins/events, use Composer patching (e.g. `cweagans/composer-patches`) so the change is declarative, tracked, and applied on every install.

### 5. Reporting upstream

Report real bugs to the module/core maintainer. Include a patch via composer-patches as a temporary workaround until the fix is released.

## Enforcement

- CI fails if any file under `vendor/` differs from the installed package (e.g. `composer install` then check git status).
- Code review rejects any diff touching `vendor/`.
- Violations are treated as high/critical issues.
